## Documentation Maintenance

Read the relevant files under `docs/` before making changes.

Update documentation only when the current GitHub issue changes:
- product behavior
- architecture
- API contracts
- important technical decisions

Do not create unnecessary documentation files.
Do not duplicate documentation across multiple files.


If the current GitHub issue conflicts with existing documentation, do not guess.
Keep the implementation scoped to the issue and note the conflict in the pull request.
